Privacy policy.

Street Expenses is a personal expense-tracking project developed and maintained by Joel Lim. This policy covers these information pages and the planned Gmail connection for the owner’s personal use.

01. Current status

The Gmail integration is not connected yet.As of the date above, Street Expenses is in setup. The owner has created a dedicated Gmail inbox and forwarded a sample transaction alert. The importer, expense backend and mobile viewer have not been implemented.

These public pages provide information only. They do not offer Google sign-in, connect to a mailbox or collect transaction data. The sections below distinguish current website practices from planned data handling for the first Gmail connection test. There is no public account registration.

02. Gmail access & data

The planned connection uses Google OAuth with the owner’s explicit consent and the gmail.readonly permission. This permission can read messages throughout the connected mailbox, even though the project intends to process selected transaction alerts. Email filters do not restrict the permission itself. A dedicated inbox is used to limit the personal mail present in that account.

Read-only access does not permit sending, editing or deleting messages, or marking them as read. Street Expenses does not request a Google password, bank credentials or access to a bank account.

The connection test is intended to access:

  • The connected mailbox address and message identifiers used to identify source emails and avoid duplicate imports.
  • Email headers and content, including sender, recipient, subject, dates, and plain-text or HTML bodies. Forwarded messages may contain additional personal information within their text.
  • Transaction details present in an alert, such as amount, currency, merchant, date, transaction reference and masked card or account details.
  • OAuth access and refresh tokens used to maintain the authorized connection, plus import status and error information needed to detect connection problems.

The first test is planned for a small set of transaction alerts. Attachment processing and access to other Google products are outside that test’s scope.

03. How data is used

Google data will be used to read transaction alerts, extract personal expense records, associate records with their source messages, prevent repeated imports, and identify details that need the owner’s review. The owner may inspect their own source messages and test results to check accuracy.

Google data will not be sold, used for advertising or credit decisions, or used to train general-purpose AI models. The project does not provide email or expense data to other users. Transfers will be limited to those needed for the disclosed functionality with consent, security purposes, or compliance with applicable law, in accordance with Google’s policy.

Street Expenses will follow the Google API Services User Data Policy, including its Limited Use requirements, for data received from Google APIs.

04. Storage & service providers

Current setup

Forwarded emails are stored in the owner’s dedicated Gmail account and handled by Google. No Street Expenses importer or expense database is currently receiving those emails. GitHub Pages hosts these public information pages; mailbox content, transaction records and OAuth tokens are not part of the website.

First connection test

The planned first test runs on the owner’s computer. OAuth credentials, any saved test output and any extracted records will be kept locally, outside the public website and source repository. Email content will be read locally to verify the connection and parsing.

Later cloud processing

A later version may use AWS Lambda for importing, Fly.io for an application API, and MongoDB for private expense storage. Those services are not connected to Gmail for Street Expenses at this stage. Before sending Gmail or expense data to them, this policy will be updated to identify the active providers, data retained, access controls and retention arrangements.

05. Data protection

The public website contains no Google client secrets, tokens, mailbox content or real transaction records. It has no form for entering credentials or financial information.

For the planned local test, authorization will take place through Google’s OAuth flow, and Gmail API connections will use HTTPS. Tokens and saved output will be restricted to the owner’s local environment and excluded from source control, public pages and ordinary diagnostic logs. These are requirements for the test; a cloud storage or security implementation is not being claimed as already operational.

06. Retention, revocation & deletion

Current forwarded emails remain in Gmail until the owner deletes them under Gmail’s retention rules. The planned read-only importer will not delete or modify those messages.

During the first local test, saved message content, extracted test records and authorization tokens will be retained only for that test and removed when it ends, unless the owner explicitly chooses to continue using them for the next stage. There is no deployed expense archive or automatic backup process at this stage. Retention and deletion for a continuing service will be documented before it is enabled.

The owner can stop the local test and revoke Street Expenses access at any time from Google Account connections. Revoking access stops future authorized mailbox reads; it does not delete records already saved locally or emails in Gmail. The owner must delete those separately. Locally retained copies and any copies the owner has backed up must also be removed when no longer needed.

For privacy or deletion questions, contact joellimruili@gmail.com. Do not include passwords, authorization tokens or full bank alerts in a contact email.

07. This website

These Street Expenses pages use no analytics, advertising scripts, cookies, browser storage, remote fonts or embedded third-party content. The example purchase on the homepage is fictional. Following an external link takes you to that provider’s website, where its own privacy practices apply.

GitHub Pages serves the public site and may process technical request information, including IP addresses, for operation and security. See the GitHub General Privacy Statement. Sending an email to the contact address also shares the message and your address with the recipient and the email providers involved.

08. Changes & contact

This policy will be updated as the project develops. Changes to Google data access, purpose, storage or sharing will be disclosed before they take effect, with renewed consent where required. The date at the top identifies the latest revision.

Developer and privacy contact: Joel Lim, joellimruili@gmail.com.
